Проект по курсу Фреймворки Python для анализа данных: восстановление данных погоды из Excel, разведочный анализ рядов и машинное обучение для прогноза температуры на 7 дней вперёд по нескольким городам.

## Цели

- Собрать единый датафрейм из **трёх листов** Excel (часть листов может быть скрыта); исправить ошибки ручного ввода, пропуски, дубликаты и проблемы типов.
- Провести **EDA**: визуализация, проверка стационарности (ADF), декомпозиция (тренд / сезонность / остатки), спектральный анализ (FFT), ACF/PACF.
- Построить признаки (лаги, скользящие статистики, календарные переменные и др.), учитывая переход к **суточной** гранулярности и таргет `temperature` через 7 дней (`shift(-7)` внутри `groupby('city')`).
- Обучить три семейства моделей из ТЗ: **Decision Tree**, **Random Forest**, **Boosting (LightGBM)** с подбором гиперпараметров через **Optuna** по MAE на validation.
- Сравнить стратегии прогноза: **рекурсивная** (одна модель на 1 шаг с подстановкой прогнозов) и **direct / model-per-horizon** (отдельные модели под горизонты 1-7).
- Оценить качество на тесте: **MAE**, **WAPE**, **MAPE**, **Directional Accuracy**, **Directional R2**; дополнительно - анализ остатков финальной модели (график по времени, гистограмма, ACF, Шапиро–Уилк).

## Ключевые результаты

- Лучшая модель на validation по MAE - **LightGBM** (ниже, чем у RF и DT).
- Финальное обучение - на объединении train+val; на тесте **LightGBM** даёт наименьшие ошибки по уровню и хорошую точность по **направлению** изменения температуры; **MAPE** интерпретируется осторожно из‑за температур около нуля.
- **Direct** точнее на дальних дней горизонта по сравнению с **Recursive** из‑за накопления ошибки в рекурсии.

## Вывод

В работе выполнен полный цикл анализа многомерного временного ряда погоды по нескольким городам: восстановление данных из Excel, унификация индекса времени, исправление ошибок ручного ввода и типичных проблем рядов (пропуски, дубликаты, выбросы, смешанные типы). После агрегации до суточной шкалы и feature engineering с лагами и скользящими признаками модели сравнивались на хронологическом разбиении train–validation–test.

Подбор гиперпараметров через Optuna показал лучшую валидационную MAE у LightGBM (~2.71), затем Random Forest и Decision Tree. Расширяющееся окно на множестве фолдов подтвердило устойчивость (средняя ошибка порядка 2.8 на неделю вперёд). На тесте LightGBM лучше воспроизводит уровни температуры и направление её изменений (Directional Accuracy ~ 80.8 %, высокий R2 прогноза относительно факта). MAPE не учитывалась как незначимая метрика из‑за нестабильности около нуля.

Сравнение стратегий Direct (семь моделей под свои горизонты) и Recursive (одна модель с подстановкой прогнозов на следующих шагах) согласуется с теорией: на дальних горизонтах точнее Direct, так как не накапливается ошибка рекурсии; на h = 1 результаты близки.

Итог: данные удалось привести к согласованному виду и использовать для осмысленного недельного прогноза; среди реализованных моделей и стратегий предпочтительны LightGBM и Direct для горизонта 7 дней.
